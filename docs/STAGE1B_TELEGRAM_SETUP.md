# تنظیم اعلان تلگرام Stage 1B

این راهنما فقط برای Workflow مورداعتماد `Trusted Stage 1B Telegram Notifier` است. اسکنر اصلی هیچ‌کدام از اطلاعات دسترسی تلگرام را دریافت نمی‌کند.

## مقادیر لازم

در تنظیمات مخزن GitHub این موارد را ثبت کنید:

### Repository Secrets

- `TELEGRAM_TOKEN`: توکن BotFather.
- `TELEGRAM_CHAT_ID`: شناسه عددی کانال با پیشوند `-100`.
- `TELEGRAM_EXPECTED_CHANNEL_TITLE`: عنوان دقیق کانال؛ باید با عنوانی که Telegram API برمی‌گرداند مطابقت داشته باشد.

### Repository Variable

- `DASHBOARD_URL`: نشانی پایدار HTTPS داشبورد Cloudflare Pages. نشانی Preview مربوط به یک Pull Request یا یک Commit را به‌عنوان نشانی دائمی ثبت نکنید.

## کنترل‌های پیش از ارسال

قبل از ثبت Claim و ارسال پیام، Workflow این موارد را بررسی می‌کند:

1. گزارش دقیقاً ۲۷ نماد Universe را داشته باشد.
2. گزارش حداکثر ۴ ساعت عمر داشته باشد.
3. سیاست گزارش `WATCHLIST_ONLY_NO_BUY_NOW_NO_SELL_NOW` باشد.
4. هر نامزد تولیدی جهت، Entry، SL، TP1، TP2 و R:R سازگار داشته باشد.
5. فرضیه و شرط ابطال واقعی و غیرخالی باشند.
6. URL داشبورد HTTPS و مقادیر دسترسی از نظر ساختار معتبر باشند.
7. ربات در کانال با عنوان دقیق تأییدشده، Administrator و دارای مجوز ارسال باشد.

اگر هر کنترل شکست بخورد، Workflow قبل از Claim متوقف می‌شود و پیامی ارسال نمی‌کند.

## رفتار جلوگیری از تکرار

- شناسه اجرای GitHub Actions کلید یکتای تحویل است.
- Claim قبل از ارسال در شاخه `telegram-delivery-state` ثبت می‌شود.
- اجرای مجدد همان Run پس از Claim، پیام را دوباره ارسال نمی‌کند.
- اگر نتیجه ارسال مبهم باشد، وضعیت `DELIVERY_UNCONFIRMED` ثبت می‌شود و ارسال خودکار مجدد انجام نمی‌شود.

این طراحی **At-most-once** است، نه تضمین Exactly-once. در خطای مبهم شبکه ممکن است پیام نرسیده باشد؛ برای جلوگیری از ارسال تکراری، ارسال خودکار دوباره انجام نمی‌شود.

## مرز ایمنی

- پیام‌ها فقط گزارش WATCHLIST هستند.
- Confidence برابر `NOT_CALIBRATED` و EV برابر `NOT_CALCULATED` نمایش داده می‌شوند.
- CVD با برچسب منبع واقعی یا `PROXY_OHLCV` / `UNAVAILABLE` گزارش می‌شود.
- هیچ حساب معاملاتی، کلید سفارش یا API معاملاتی استفاده نمی‌شود.
- هیچ سفارش یا معامله‌ای اجرا نمی‌شود.
