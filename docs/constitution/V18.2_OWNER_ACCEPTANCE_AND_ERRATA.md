## 2. Binding amendments

### AM-01 — C++ is the only production implementation language

- C++ owns all production L1 data acquisition, normalization, validation, provider selection, L2 computation, strategy decisions, risk gates, artifact publication and L3 Telegram delivery.
- Python is legacy/auxiliary only. It may remain for historical tests, non-authoritative research or migration diagnostics, but it is not a production market-data or signal path.
- The hybrid proposal in V18.2 Part XIV (Python L1 → C++ L2/L3) is superseded.
- No old Python workflow may publish a competing signal stream, write authoritative production state or send user-facing signals.

### AM-02 — Telegram is the only user-facing delivery channel

- Telegram is the sole user-facing delivery channel for routine signals, status and reports.
- Web dashboard, browser application, email, Railway, n8n or another notification channel is not a production dependency or alternative user delivery route.
- Historical dashboard/web sections in V18.2 are non-operative where they conflict with Telegram-only delivery.
- Internal GitHub repositories, Actions and runtime artifacts are engineering/evidence surfaces, not user-side pipeline dependencies.

### AM-03 — Backend-owned public data; no user-side connectivity

- GitHub Actions/C++ workers fetch permitted public market data.
- The user never logs into, connects to or operates an exchange, TradingView, CoinGecko or another provider for the pipeline.
- Public unauthenticated market-data APIs are allowed. User exchange-account access, private exchange endpoints, trading credentials, user balances/positions and order endpoints are prohibited.
- Geography or user-side provider access does not determine backend source availability; provider reachability is measured from the actual runner.

### AM-04 — Manual trading only

- The system is read-only decision support.
- No order placement, modification, cancellation, automated execution, copy trading or exchange-account connection is permitted.
- A Telegram signal is a recommendation artifact only; the user independently decides whether to trade.

### AM-05 — C++20 is an implementation choice, not a source mandate

V18.2 §0.6 does not prescribe a C++ standard version. The repository's verified Ubuntu 24.04 toolchain currently builds with C++20. Therefore C++20 is the current implementation configuration, selected from observed compiler/build compatibility. It must not be misquoted as a literal requirement of V18.2.
