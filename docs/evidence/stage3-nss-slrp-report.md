## Objective

Implement the five-component NSS contract without fabricating raw-to-score transforms, replacing missing values with zero, or confusing REAL and PROXY inputs.

## Source contract

`NSS = 0.30*NSS1 + 0.20*NSS2 + 0.20*NSS3 + 0.15*NSS4 + 0.15*NSS5`

- NSS1: Open Interest Growth.
- NSS2: Healthy Funding.
- NSS3: Basis Expansion.
- NSS4: Volume Expansion.
- NSS5: Pre-Breakout Compression.

All component scores must be deterministic, versioned, point-in-time available and normalized to [0,1]. Missing values cannot be replaced with zero and missing weights cannot be redistributed.

## Numeric acceptance criteria

1. Exactly five ordered components and canonical weights: 0.30 / 0.20 / 0.20 / 0.15 / 0.15.
2. Each component score is finite and within [0,1].
3. Each component has a non-empty definition/version identifier.
4. Each availability timestamp is positive and no later than decision time.
5. Full NSS is emitted only with 5/5 valid REAL components in v1.
6. Missing IDs are reported; no zero fill or weight renormalization.
7. Identical inputs produce identical scores.
8. PROXY inputs are rejected by v1.
9. C++ build and CTest pass under warning-enabled C++20.
10. Real BTC plus at least one eligible altcoin are assessed from L1.
11. No actionable trade is emitted by this resilience stage.
12. Final stage result must have a real Telegram delivery receipt.

## Source limitations requiring measured diagnosis

V18.2 defines the NSS component meanings and weights, but does not specify the raw-to-score mathematical transforms for all five components. The current Stage 1 L1 contract contains OHLCV, funding and open interest; it does not define a real spot/perpetual basis series.

The v1 probe therefore leaves scores unavailable rather than inventing transforms or basis values. This is an implementation guard, not yet a measured v1 FAIL until the live workflow completes.
