# V18.2 Legacy Automation Quarantine

**Purpose:** prevent legacy Python automation from running beside the canonical V18.2 C++ production pipeline.

## Audit findings on the original main tree

Five scheduled workflows were found:

| Workflow | Schedule | Legacy function | Risk |
|---|---:|---|---|
| `signal_bot.yml` | Every 4 hours | Python Trader_me Stage 1B signal bot | Could continue publishing a second, non-canonical signal stream |
| `research_outcome_tracker.yml` | Every 15 minutes | Python research outcome tracker | Unnecessary automatic legacy compute and branch writes |
| `stage1b-scheduled.yml` | Every 4 hours | Python LRT 15m data maintenance | Competes with C++-only production boundary |
| `orderbook-l2.yml` | Hourly | Python public L2 collector | Automatic legacy compute and artifact storage |
| `test_okx_endpoints.yml` | Weekly | Python endpoint diagnostics | Automatic legacy compute and artifact storage |

## Quarantine changes in this branch

- Removed automatic `push` and `schedule` triggers from all five workflows.
- Kept manual `workflow_dispatch` for four diagnostic/maintenance workflows.
- Disabled the legacy Python `signal_bot` job with an unconditional false job gate. Manual dispatch cannot run it.
- Removed artifact-upload steps from the four retained manual workflows.
- No production C++ or Telegram V18.2 code is changed by this quarantine branch.

## Why this is required

V18.2 defines C++ as the only production language and Telegram as the only delivery channel. Leaving the old Python signal bot on a four-hour schedule could create duplicate and conflicting user-facing signals. Legacy scheduled workflows also create avoidable GitHub Actions and artifact-storage usage.

## Release condition

This PR is Draft and has not changed `main`. The original main tree remains the base state until the owner approves and merges this quarantine PR. Until merge, the five schedules remain active on the default branch.
