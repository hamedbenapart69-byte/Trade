# V18.2 Legacy Automation Quarantine

**Canonical decision:** UNIFIED_CRYPTO_FUTURES_SYSTEM_V18.2_MASTER  
**Implementation PR:** [#152](https://github.com/hamedbenapart69-byte/Trade/pull/152)  
**Merge commit:** `f55f443dcf61170dd32a6cf6119450cd4798a879`  
**Merged:** 2026-11-18  
**Current disposition:** QUARANTINE MERGED AND VERIFIED ON `main`

## Purpose

Prevent legacy Python automation, duplicate signal publication, and paid deployment paths from operating alongside the V18.2 C++ production pipeline.

## What was quarantined

PR #152 changed 19 workflow and test files. The pull request is merged. A direct comparison of the changed-file blob SHAs on `main` and the quarantine branch confirmed that all 19 files match the merged quarantine implementation.

- `signal_bot.yml`: manual dispatch only; the legacy signal job has an unconditional `if: false` guard.
- `v5-signal-autopilot.yml`: manual dispatch only; the legacy job has an unconditional `if: false` guard.
- `deploy-railway.yml`: manual dispatch only; the paid deployment job has an unconditional `if: false` guard.
- `research_outcome_tracker.yml`, `stage1b-scheduled.yml`, `orderbook-l2.yml`, and `test_okx_endpoints.yml`: their former schedule/push triggers were removed. They retain manual-only maintenance or diagnostic entry points; they are not the canonical production signal pipeline.
- Legacy downstream persistence, dashboard-publication, and Telegram-handler workflows were modified by the same merged PR to remove automatic workflow-run delivery/persistence paths and prevent duplicate production outputs.
- `telegram_channel_check.yml` is manual-only. The old `telegram_probe.yml` path was quarantined.
- Railway deployment and legacy V5 signal/dashboard automation are disabled.

## Current operating boundary

- Production implementation: C++20.
- Public market data is collected by GitHub Actions.
- User-facing delivery: Telegram only.
- No user exchange-account connection, private trading credentials, or order execution.
- Python remains available only for legacy tests or explicitly manual maintenance/diagnostics; it is not the production signal runtime.
- Cloudflare Pages may still run its repository build/check, but it is not the user delivery channel or a dependency of the trading pipeline.

## Residual note

Manual-only maintenance workflows are intentionally retained. Their existence does not mean that a parallel production signal stream is active. Any future automation trigger, delivery route, or production-language change must be reviewed against V18.2 before activation.
