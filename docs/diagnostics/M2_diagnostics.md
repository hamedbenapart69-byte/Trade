## Failure prediction
1. Schema compatibility failure: consumers might assume a fixed root schema. Mitigation: additive fields only; existing keys retained. Early warning: JSON validation or dashboard fetch failure.
2. Missing Telegram response ID: a send may succeed but the client return may be absent/invalid. Early warning: `message_id_current=null` despite delivery status; current code only persists positive integer IDs.
3. Publication ordering race: writing signals.json before sending would omit IDs. Root fix: call notifier first, then `publish(payload)`. Early warning: run summary has IDs but branch JSON does not.
4. Duplicate/partial delivery: image send may fail and text fallback may succeed. The ID recorded is the returned ID from the successful fallback. Existing idempotency state remains in place.
5. Audience destination missing: M1 proved `TELEGRAM_AUDIENCE_CHANNEL_ID` empty. Audience IDs remain null; no fabricated delivery claim is made.

Rollback: revert `5f73ef75e407c2f9bdc610100a041a89e6bb3be8`. The previous pipeline code is at parent `fdbcab0e37821eb67c983b276e48f81d6a5d9642`.

## Post-change self-check
1. Regression: all 160 pytest tests passed; the pipeline's own 33 unittest tests passed and the end-to-end JSON validation passed.
2. Root cause: IDs were previously discarded because `send_message`/`send_photo` return values were ignored and `publish(payload)` ran before notification. Both causes were addressed.
3. Long-term risk: if Telegram accepts a send but the runner loses the response before receiving Message, a real post may not have a persisted ID. This is an API delivery uncertainty and should not be silently retried.
4. Fragile assumption: Telegram's Python client returns a Message with positive integer message_id; verified in M1 and live M2.
5. Independent break attempt: if publication is moved before notify again, the branch JSON will omit IDs; the new regression test covers the payload mutation, while the live run proves branch persistence.
6. Audience channel: not configured in GitHub Actions environment, so the second field stays null.
