# قرارداد دسترسی کاربر و تحویل سیگنال

## اصل غیرقابل‌تغییر
کاربر فقط خروجی نهایی را در کانال تلگرام دریافت می‌کند. دریافت داده، تحلیل، اعتبارسنجی، انتخاب و تعویض ارائه‌دهنده و زمان‌بندی، همگی در محیط اجرای سمت سرور انجام می‌شوند.

## مسئولیت سیستم
- اجرای اسکن و دریافت داده از APIها و ابزارهای عمومی یا مجاز، از سمت GitHub Actions یا runner سمت سرور.
- انتخاب ارائه‌دهنده بر اساس کیفیت، تازگی، پوشش، پایداری، هزینه و قابلیت دسترسی از محیط اجرا.
- تعویض خودکار ارائه‌دهنده پس از خطا، timeout، پاسخ نامعتبر یا داده ناکافی.
- ارسال سیگنال و گزارش روزانه، از جمله نبود سیگنال یا افت کیفیت داده، به کانال تلگرام.

## چیزی که از کاربر خواسته نمی‌شود
- اتصال حساب صرافی یا ساخت API key معاملاتی.
- ورود یا اتصال به TradingView یا ابزارهای تحلیل.
- ارائه VPN، تغییر IP یا رفع محدودیت‌های سرویس‌دهنده.
- نصب نرم‌افزار، اجرای CLI یا راه‌اندازی محلی.
- استفاده از داشبورد برای مشاهدهٔ سیگنال‌ها؛ کانال تلگرام رابط تحویل کاربر است.

## مرزهای ایمنی و صداقت داده
- فقط دادهٔ عمومی یا داده‌ای که استفادهٔ سمت سرور آن مجاز است دریافت می‌شود.
- کلیدهای ربات تلگرام و هر credential لازم برای سرویس‌دهنده فقط در Secrets سمت سرور نگهداری می‌شوند؛ از کاربر کلید معاملاتی درخواست نمی‌شود.
- هیچ اتصال حساب معاملاتی و هیچ سفارش خودکاری وجود ندارد.
- دادهٔ اسپات جایگزین OHLCV فیوچرز نمی‌شود.
- دادهٔ جانشین با PROXY و دادهٔ مفقود با UNAVAILABLE مشخص می‌شود.
- شکست همهٔ منابع باید به وضعیت صادقانهٔ MARKET_DATA_DEGRADED یا UNAVAILABLE منتهی شود، نه ساختن سیگنال.

## معیار پذیرش
1. اجرای داده‌گیری بدون نیاز به حضور یا اتصال کاربر ممکن باشد.
2. خطای هر provider به تلاش برای provider بعدی منجر شود.
3. پیام سیگنال و پیام روزانهٔ بدون سیگنال/دادهٔ مختل‌شده از مسیر تلگرام ارسال شوند.
4. نبود دادهٔ واقعی هرگز با دادهٔ ساختگی یا دادهٔ اسپاتِ فیوچرزنما پوشانده نشود.
5. کاربر فقط برای مشاهدهٔ خروجی به تلگرام نیاز داشته باشد.

این قرارداد دربارهٔ دسترسی کاربر است؛ دسترسی واقعی runner به هر API همچنان باید در اجرای واقعی اندازه‌گیری شود و از پیش فرض گرفته نشود.
